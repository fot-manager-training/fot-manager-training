# fot-manager-training.ru: Лиса с прямым подключением DeepSeek

Текущий установщик `install_attachments.py` устанавливает интерфейс и независимый сервер Лисы на существующий VPS. Чат обращается к `/api/lisa/` своего домена, сервер — к `api.deepseek.com`. Посетителю не нужен доступ к `chatgpt.site`. Материалы RAG, шаблоны сравнения, роль Сбера, ограничения тем и потоковая генерация совпадают с облачной версией. Содержимое фото передаётся модели после локального OCR; DeepSeek не получает исходные изображения.

Установка из ветки `deploy-cloud-agent` публичного репозитория: скачайте `install.py` и запустите Python от root. При первом запуске установщик запрашивает ключ DeepSeek скрытым вводом, проверяет доступ и баланс. Ключ сохраняется только в `/etc/fot-manager-training/lisa.env`, права 0600; systemd читает файл до запуска процесса от пользователя `fottraining`. Повторная установка использует существующий ключ. В публичной статике и репозитории ключа нет.

Службы: существующая `fot-manager-training.service` обслуживает обучение, статистику и OCR на 127.0.0.1:8766; новая `fot-lisa.service` обслуживает чат на 127.0.0.1:8767. Nginx направляет `/api/lisa/attachments` и вложенные health-запросы в OCR, остальные `/api/lisa/` — в Лису с отключённой буферизацией SSE. Публичные новые порты не нужны. DNS и сертификаты не меняются. Используется существующий Node.js 18+ либо официальный Node.js 22 LTS с проверкой SHA256.

База банков хранится отдельно в `/var/lib/fot-manager-training/lisa.sqlite3`. Начальный снимок не заменяет уже существующие записи. Таймер `fot-lisa-refresh.timer` ежедневно в 08:00 Europe/Moscow обновляет фиксированные официальные источники; ошибки не затирают последний успешный снимок и не меняют дату проверки. В диалоге нет поиска по сайтам банков. RAG содержит 80 фрагментов предоставленных материалов, источники открываются на собственном домене.

Статистика и ключ посетителя в `/var/lib/fot-manager-training` не сбрасываются. Облачная и доменная статистика не объединяются. Установщик проверяет SHA256 каждого файла, создаёт SQLite backup и копии конфигурации, переключает symlink, проверяет службы и возвращает прежний релиз при сбое. Путь к ручному `rollback.sh` выводится перед переключением.

Вложения: JPG/PNG/WebP, PDF, DOCX, XLSX, PPTX, TXT/CSV; максимум 10 МБ на файл и 3 файла на сообщение. Фото и сканы PDF распознаются Tesseract rus+eng. Оригиналы удаляются после распознавания; извлечённый текст можно исправить перед отправкой. Лимит 18 000 символов на файл и 60 000 на вложения истории. Текстовые PDF — до 20 страниц, сканы — до 6, PPTX — до 20 слайдов; изображения внутри текстовых PDF/PPTX прикладываются отдельно. XLSX — до 8 листов, 500 строк, 30 столбцов; формулы не вычисляются.

Проверки: `node tests/local-lisa.mjs`, `node tests/attachments.mjs`, `node tests/streaming.mjs`, `python tests/attachment-install.py /path/to/package`. `tests/chat-send-dom.mjs` проверяет реальный DOM чата через временную установку linkedom (`DOM_TEST_MODULE=/path/to/linkedom/esm/index.js`): нажатие кнопки, отправку одного фото, сбой health, восстановление текста и вложения при ошибке, повторную отправку. Браузерный визуальный QA не подменяется этим тестом.

После установки проверяются `deployment-info.json` (release `deepseek-domain-20261029`), `/api/lisa/health` (ready true, provider deepseek), `/api/lisa/attachments/health`, затем ККСБ → лиса → сообщение с фото. Публикация в GitHub или облаке сама по себе не обновляет VPS: установщик необходимо выполнить на сервере.
